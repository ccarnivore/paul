# Selective historical reads in Claude Code

Run through Bash: `node "~/.claude/paul-framework/runtime/cli.js" COMMAND`. All commands below are read-only. Do not wrap output in head/tail: it can discard truncation warnings or mandatory rules.

- `history --query "CSV Format Lieferant SysConfig" --limit 5`: case-insensitive individual terms, any-term matches ranked by distinct term coverage. Searches SUMMARY and accompanying RESULT. Results include exact source lines and bounded previews, never unlimited evidence rows. `--offset N` pages ranked entries; `--budget CHARS` bounds each response (default 6000, minimum 2000). No hits does not prove no applicable history.
- `handoff --plan 17-01`: bounded outcome/issues/deviations/decisions followed by task/AC/file/check/skill records. SUMMARY corrections outside a matching close receipt are included as extra sections, so they cannot disappear behind older RESULT data. For a matching RESULT, entries give `field` and zero-based `index`; `counts` lists all records, including empty arrays. `--offset N` pages entries, `--limit N` limits count (default 8, max 20). Default output budget 6000 characters. Relevant truncated entries need full reads before reuse.
- `result-section --plan 17-01 --field acceptance --item AC-2`: full stored AC evidence, including limitations and actual waivers. `--item` accepts ID or zero-based index. Omit it to read an entire field. Fields: outcome, issues, deviations, decisions, acceptance, tasks, files, verification, skills. Default page 4000 characters, max 16000; continue `--offset nextOffset`. `planMatches: false` means historical evidence, not evidence for this revision.
- Legacy handoff without a matching RESULT lists SUMMARY headings, including unknown/German headings. Read selected text with `section --file phases/.../17-01-SUMMARY.md --heading "Issues Encountered" --limit 4000 --offset 0`. Headings with duplicate names need native Read with listed line offsets. Plain files without headings use native Read. Without limit/offset, section preserves the existing full-read behavior for required constraints.
- `plan-check --plan 18-01`: parsed AC/task inventory, hash and UTF-8 bytes; a 6 KB soft target. It validates syntax, not feasibility or scope. Keep requirements even when exceeding the target. Correct selected passages with Edit, do not print/write another whole PLAN merely for size.

Every excerpt marks truncation and every page gives nextOffset when more entries/text remain. Pagination does not select which facts matter: read all applicable decisions, unresolved issues, waivers and qualifications. Compare source hashes when reusing prior output. No command grants approval, changes legacy status or replaces required fresh tests.
